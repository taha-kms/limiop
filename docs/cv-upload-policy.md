# CV upload policy

CV documents are sensitive and hostile input. This policy applies before a
document reaches storage or a parser. Passing it does not make a PDF trusted.

## Accepted input

- Version one accepts PDF only.
- The client filename must have a `.pdf` extension, but the extension never
  decides the file type. The declared media type must be `application/pdf` and
  the content must begin with the PDF signature `%PDF-`.
- The default limit is 5 MiB (5,242,880 bytes), including the exact boundary.
  `SKILLSYNC_CV_MAX_UPLOAD_BYTES` configures the limit and
  `SKILLSYNC_CV_ALLOWED_FORMATS` configures enabled supported formats.
- Empty files are rejected.

The initial signature check rejects obvious mismatches and extension-only
bypasses. The PDF parser remains responsible for rejecting malformed,
encrypted, truncated, or otherwise unreadable PDF content.

## Filename handling

Client filenames are display metadata only. They must be non-empty, no longer
than 255 Unicode code points, have no leading or trailing whitespace, and
contain no path separators, control characters, or Unicode format characters.
The service never uses a client filename as a storage key, filesystem path,
parser option, log field, or control-flow value. Storage identifiers are
generated by the server.

## Ownership and retention

- An authenticated user owns every CV record and its stored object. Access is
  always checked against that owner; knowing an identifier or storage key is
  not authorization.
- Accepted CVs and extracted text are retained until the owning user deletes
  the CV, replaces it under an explicit product flow, or deletes the account.
  Version one has no time-based expiry.
- Rejected uploads are not persisted. If storage or metadata creation fails,
  the operation removes any partial object and row before reporting failure.
- CV bytes, extracted text, storage keys, and client filenames are not logged.

## Failure behavior

Rejections expose a stable reason such as invalid filename, empty file, size
limit, unsupported media type, or unsupported content. Responses do not echo
the hostile filename or file content. A rejected file is never parsed, and
parser failures never return extracted document content. CV text is plain text
only and must be escaped by any renderer; it is never accepted or served as
markup.

## PDF parsing

Accepted storage does not make a PDF safe to parse. Text extraction runs in a
disposable subprocess and terminates that process at the configured deadline.
It independently enforces the stored-file checksum and size, page count, and
normalized text length. The defaults are 20 pages, 100,000 text characters,
and five seconds; the `SKILLSYNC_CV_PDF_*` settings configure them.

Encrypted, malformed, over-limit, timed-out, and image-only documents return
distinct content-free failure reasons. Successful extraction returns normalized
plain text and a page count. It does not render PDF content, interpret markup,
extract skills, or update a candidate profile.
